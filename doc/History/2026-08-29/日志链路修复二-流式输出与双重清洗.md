# 日志链路修复（二）：流式输出 + 双重清洗

> 类型：缺陷修复（用户实测反馈迭代）· 日期：2026-08-29

- 实时输出重做：执行器从「按行 readline」改为「chunk 流式推送」（`stream.on('data')` + `StringDecoder`），进度条、无换行输出可实时滚动显示，不再等整行。
- 乱码（ANSI）修复：新增 `cleanLogText()`（剥离 ANSI OSC/SGR/CSI 控制符与 `\r`）；UTF-8 逐块解码，检测到替换符时按 GBK 回退解码（`iconv-lite`），运行收尾对整段缓冲重解码。
- 实时区展示与历史展示统一过 `cleanLogText`：即使收到旧主进程推送的原始行也能显示干净；旧历史记录展示时清洗、不改库。
- 实时区文本改为连续累积渲染（替代『每 chunk 当一行再拼接』），避免 chunk 边界产生假换行；实时区上限 200 万字符，单次入库 5MB。
- 订阅去重：preload 改为单次全局 `ipcRenderer.on` + Set 广播，避免多订阅重复行。
- 面板滚底：`requestAnimationFrame` 强制滚动到底。
- 排查结论：用户反馈「还是乱码 / 不实时」的根因是运行中的 dev 主进程未重启（旧主进程 12:18 启动后一直驻留，新代码 12:40 才写入 `out/`），已重启 dev 并重新打包 release .app；验证：typecheck / eslint / build / pack 通过，asar 内确认含新逻辑。
